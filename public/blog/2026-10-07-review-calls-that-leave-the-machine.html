Review the Tool Calls That Write, Spend, or Leave the Machine

Published on 2026-10-07 by Igor Ganapolsky

A person should see the calls that change something. Reads can run when a policy already allows that tool and those arguments.

The Failure Mode

Reviewing every tool call does not scale, and reviewing none of them leaves a coding agent free to write files, spend money, send messages, or leave the machine. A review after the call is a transcript of damage that already happened.

Architectural Resolution

ThumbGate checks the tool name and the arguments before the call runs. The gate shows one line of intent for a write, a payment, a message, or a command that leaves the machine: the command, the path, or the destination. A read or a local lookup proceeds when the policy already allows that tool and those arguments.

function reviewBeforeRun(toolName, args) {
  const command = String(args.command || '');
  const leaves = toolName === 'Bash' && /\b(curl|ssh|scp|git\s+push)\b/.test(command);
  const writes = toolName === 'Write' || toolName === 'Edit';
  const sends = toolName === 'SendMessage' || toolName === 'WebFetch';
  if (leaves || writes || sends) {
    return { decision: 'review', show: command || args.path || args.url || toolName };
  }
  return { decision: 'allow' };
}
