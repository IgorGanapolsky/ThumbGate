Learn / Deploy-proof gate

Stop your AI agent from saying "deployed" without proof

4 min read · For developers who ship with Claude Code

TL;DR: Coding agents say "it's live" before anyone checked. ThumbGate's deploy-proof gate is a Claude Code Stop hook: if the reply claims a deploy and shows no proof from production, Claude Code hands the reply back to the agent with instructions to run the check and paste the output. It is on by default in ThumbGate 1.43.0 and later.

The failure it targets

An agent merges a PR and writes "Deployed, it's live." The deploy is still building, or it failed, or it went to the wrong service. You believe it because the sentence sounds finished. We hit this ourselves: on 26 March 2026 an agent working on ThumbGate said "deployed" three times while the production container was failing to rebuild. The fix we used on our own repo is the hook this page describes, now generalized so any project can use it.

What it does

  1. When the agent finishes a reply, Claude Code runs the Stop hook that npx thumbgate init installs (thumbgate claim-stop-check). The ThumbGate Claude plugin runs the same hook.
  2. The hook looks for a deploy claim: "deployed", "shipped", "now live", "is live", "in production". It skips "not deployed yet", "once it is deployed", "will be live", and questions.
  3. It looks for proof in the same reply, or in a tool call from the same message: curl output against the production host, a /health JSON snapshot, a buildSha, an HTTP 200 from the host, or a CI line you name, such as "Deploy verified".
  4. Claim and no proof: the reply is blocked once, and the agent is told to run the check and paste the output, or to say "not verified".

Set your production hosts

Without configuration, proof from any https host counts. To require proof from your real production host, add .thumbgate/deploy-proof.json:

{
  "hosts": ["app.example.com"],
  "sentinels": ["Deploy verified"]
}

Or set THUMBGATE_PROD_HOSTS=app.example.com,api.example.com. Turn the gate off with THUMBGATE_DEPLOY_PROOF_GATE=0.

What it does not do

  • It blocks once, not forever. Claude Code gives the agent one correction turn, and ThumbGate allows that retry so a reply can never loop. An agent that ignores the instruction can still repeat the claim on the retry.
  • It checks that proof is present, not that it is true. It does not call your server itself. A pasted health response from the wrong environment passes unless you set your hosts.
  • It matches words. "The new build is up" is not a deploy claim to this hook.
  • Claude Code only. Cursor, Codex, and other agents do not get this Stop-time check yet.
  • Other completion claims, such as "done" or "fixed", get a reminder by default and a block only in strict mode (THUMBGATE_STRICT_ENFORCEMENT=1).

Make "it's live" mean something

Install ThumbGate in a Claude Code project. The deploy-proof gate is on by default.
