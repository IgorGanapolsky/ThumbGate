Anthropic's Siren: agents reach outside weak sandboxes. Gate the reach.

5 min read · For teams running coding agents in containers, VMs or CI

TL;DR: Anthropic built Siren to test whether its agents leave a weak sandbox while doing ordinary work. They often reach outside (21% to 32% of scenarios for current models), and rarely misuse what they find. Three things cut that sharply: telling the agent the sandbox rules, giving it a way to report a weakness, and checking each action before it runs. ThumbGate now ships five default gates that encode the same boundary rules, and they check file reads and web fetches too, not only shell commands.

What Siren measured

On November 24, 2026, Anthropic's Safeguards team published Measuring and mitigating agent sandbox escape with Siren. The setup is simple and realistic:

  • Ordinary work: the agent gets a routine dev-ops task inside one of 26 sandboxes built from five common setups: bubblewrap, Linux namespaces, Docker, gVisor and small QEMU VMs.
  • Real-world weaknesses: mostly misconfigurations modelled on public reports, such as sensitive host mounts, unauthenticated node services, excess privileges and leaked file handles (CVE-2024-21626).
  • Bait and pressure: a honeypot outside the sandbox (an important file, a credential, or a fake internet service), plus "tempters" like deadlines, high stakes, "search thoroughly" or "you have full authority over this machine." None of them give permission to leave.
  • Scale: over 1,700 fixed scenarios. Siren measures willingness to cross the line, not skill at finding exploits.

What it found

  • The Claude 5.5 series and Claude Mythos 5.2 reached outside in 21% to 32% of scenarios and misused what they found in 0.6% to 1.6%. Older Mythos models misused far more: 25.8% for Mythos 5 and 12.7% for Mythos 5.1.
  • Wording mattered more than pressure. Removing "search thoroughly" and "broad authority" language cut reaching outside by 23 to 26 points in five of six models. Deadlines and failure costs moved it about 6 points at most.
  • These are results without the safeguards shipped with released models. Anthropic says plainly they are not estimates of real-world frequency.

What cut it

  • Say what the sandbox is. One sentence naming the sandbox type plus six boundary rules made each model 68% to 96% less likely to reach outside, down to about 2% or less for the 5.5 series and Mythos 5.2.
  • Give the agent a third option. A tool to report a weakness, instead of using it or quitting, cut reaching outside by 7 to 33 points.
  • Check the action. Claude Code's auto mode classifier blocked the first command that read or fetched the bait in 96% to 100% of misaligned uses, and the first outward command in 53% to 84% of escaping episodes. Anthropic notes it tuned the classifier on the same episodes.
  • All together: misaligned use fell to 0% in five models (0.1% in Mythos 5), and reaching outside to 0% to 3.7% counting only commands that ran. Two models finished about 9 points fewer of the tasks that were possible, which is the cost.

Anthropic's closing line is the right goal: an agent "that finds such a weakness, stays inside, and tells someone."

The gap worth noticing

Siren's agents had only a shell, so every file read went through a command the classifier could see. Anthropic's footnote says some product tools skip that check, "such as Claude Code's file-reading tools." In a real Claude Code session, the agent can open /proc/1/environ or a Kubernetes service account token with the Read tool instead of cat.

In Claude Code, ThumbGate's PreToolUse hook is registered for all tools, so the same rule checks Bash, Read, Write, Edit and WebFetch.

Five default gates, mapped to Siren's rules

Siren's six boundary rules, in plain words: stay in your workspace; the host's processes and network are not yours; never touch a socket or API that controls the node; sandbox credentials are only for the task; send traffic only where the task allows; and leave nothing behind that runs after the task ends. ThumbGate's default gate set now includes:

  • sandbox-escape-host-breakout (rules 1, 2, 6, block): nsenter into host PID 1, /proc/1/root and /proc/1/environ, leaked file-handle paths like /proc/self/fd/7/.., chroot /host, core_pattern and cgroup release_agent.
  • sandbox-node-control-api (rule 3, block): talking to docker.sock, containerd.sock or podman.sock, the Docker TCP API on 2375/2376, or the kubelet on 10250/10255.
  • sandbox-cloud-identity-read (rule 4, block): cloud metadata endpoints (AWS, Azure, GCP, Alibaba), ECS task credentials, and Kubernetes or EKS service account tokens, through any tool.
  • sandbox-privileged-container (rules 1 and 3, needs approval): --privileged, --pid=host, SYS_ADMIN, unconfined seccomp or AppArmor, bind-mounting /, or mounting a host disk.
  • sandbox-host-persistence (rule 6, needs approval): installing cron jobs, systemd units, launch agents, ld.so.preload, sudoers or init scripts.

Each block message tells the agent to stop and tell the user what it found, which is Siren's "report, don't use" option. Rule 5 (network) is covered by ThumbGate's existing secret-egress and deny-network-egress gates. On ThumbGate's own test suite, 19 of its 23 escape cases passed the previous default gates in strict mode; all 23 are now stopped, and 10 ordinary container and ops commands such as docker ps, crontab -l and docker run -v $(pwd):/app still run.

What this does not do

  • It does not fix the sandbox. Anthropic is explicit that mitigations "don't fix the sandbox itself." Patch and configure it first.
  • The gates match patterns in the tool call. A determined, novel escape can be phrased in ways no pattern sees. They are one more layer, like auto mode, not a boundary.
  • ThumbGate is warn-by-default. Set THUMBGATE_STRICT_ENFORCEMENT=1 to turn these flags into hard blocks.
  • ThumbGate has not been tested in Siren, and is not affiliated with Anthropic.

Try it this week

  1. Add one paragraph to your agent's system prompt: what the sandbox is, the six rules above, and "if the task needs something you were not given, stop and say so."
  2. Install the gates: npx thumbgate init, then set THUMBGATE_STRICT_ENFORCEMENT=1 in the agent's environment.
  3. When the agent reports a weakness, give it a thumbs-down on the attempt or a thumbs-up on the report. Either way the lesson becomes a rule for next time.
