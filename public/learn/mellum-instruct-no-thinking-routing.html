Learn / Thinking vs instruct routing

JetBrains Mellum2.1 Instruct skips thinking on routine agent work. Route your agents the same way

4 min read · For developers running Claude Code and other coding agents

TL;DR: On November 25, 2026 JetBrains released Mellum2.1 Instruct, an open-weights coding model that answers without a chain of thought. In JetBrains' agent tests it used about 45% fewer tokens per task than Mellum2.1 Thinking. Most of an agent's day is small edits and tool calls, where thinking adds time without adding quality. ThumbGate's model routing now says, per task, whether a reasoning step is worth paying for, and can run both Mellum2.1 models on your own machine.

What JetBrains shipped

These points come from The New Stack's report and the model cards on Hugging Face, linked below.

  • Same model, no thinking step. Mellum2.1 Instruct is a 12-billion-parameter mixture-of-experts model that activates 2.5 billion parameters per token. It got the same repository-level reinforcement learning as Mellum2.1 Thinking.
  • Built for sub-agents, tool loops and chat. In JetBrains' words, "reasoning adds time and computing resources without adding quality," especially locally, where "every extra thinking token adds to the time you're waiting."
  • Fewer tokens. About 5,600 tokens per agent task against 10,100 for Thinking, a 45% cut, or 73% when tool-call tokens are left out.
  • Where it falls behind. The two score nearly the same on SWE-bench Verified (Instruct 40.4%), but on hard algorithmic and math benchmarks such as LiveCodeBench and AIME, JetBrains says Thinking "remains the better choice."
  • Open weights. Apache 2.0 on Hugging Face, with a GGUF build for low-memory machines and a multi-token prediction head that JetBrains says speeds generation up to 1.8 times.

Why this matters for agent guardrails

As agents hand work to other agents, the expensive mistake is no longer only a bad tool call. It is also paying a reasoning model to rename a variable a thousand times a day. The fix has the same shape as a gate: decide before the call, from what you know about the task.

ThumbGate already works that way for enforcement. Its PreToolUse gate check matches your prevention rules without calling a language model, so blocking a known-bad action costs no tokens. The new routing applies the same idea to the models your agents use around it.

What ThumbGate does now

  • A reasoning mode on every routing plan. recommendExecutionPlan returns reasoningMode: instruct for code edits, tool use, extraction and anything tagged routine, sub-agent or tool-loop; thinking for debugging, architecture, algorithmic and math work, or tags like hard and investigate.
  • Escalate after failure, not before. A task that fails twice without thinking switches to thinking, using the same retry threshold as tier escalation.
  • A local Mellum family. THUMBGATE_LOCAL_MODEL_FAMILY=mellum maps the normal, critique and compaction roles to Mellum2.1 Instruct and the thinking role to Mellum2.1 Thinking. Any role can still be overridden with THUMBGATE_MODEL_ROLE_<ROLE>.

What it does not do

  • It does not download or serve a model. You run the GGUF or safetensors build with your own OpenAI-compatible server.
  • It does not change how gates block. Enforcement still happens in ThumbGate's PreToolUse hook, with or without a local model.
  • The 45% figure is JetBrains' own measurement on its own tasks. Your savings depend on your workload.

Try it

  1. Install ThumbGate in a project: npx thumbgate init.
  2. Serve JetBrains/Mellum2.1-12B-A2.5B-Instruct-GGUF, and the Thinking build if you want both, with a local OpenAI-compatible server.
  3. Set THUMBGATE_LOCAL_MODEL_FAMILY=mellum for routing.
  4. For the dashboard's chat with your lessons, set THUMBGATE_LOCAL_LLM_ENDPOINT to that server and THUMBGATE_LOCAL_LLM_MODEL to the Instruct model, so questions never leave your machine.
