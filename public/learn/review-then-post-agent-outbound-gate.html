Review, then post: the draft-first rule for agents that talk to the outside world

4 min read · For founders and developers who let an agent write emails, replies or posts for them

TL;DR: A new wave of AI growth tools, such as HeyCatch, drafts social replies, posts and blog articles for solo founders every day. The design choice that makes them safe to use is simple: the agent drafts, a person reviews, then it posts. Your coding agent has the same reach once you connect Gmail or Slack to it, and usually no such stop. ThumbGate puts it at the tool call: drafts are allowed, sends are held until a person approves that exact message.

Why a send is different from every other action

Most agent mistakes can be undone. A bad edit gets reverted, a broken branch gets reset, a wrong file gets restored from git. An email to a customer, a reply on Reddit or a post on X cannot be called back. It is read, screenshotted and sometimes reported. Platforms also watch how often an account posts, so a burst of agent replies can get an account limited or banned.

That is why the better growth agents do not post on their own. They write the reply in your voice, show it to you, and send it only after you approve it.

The same problem inside Claude Code

Connect a mail or chat tool to a coding agent and it can send as you. A long session asked to "follow up with the people who signed up" can write twenty emails and send them, and the instruction in your prompt that says "show me first" is exactly the kind of rule that gets lost after a context compaction. A hook runs on every tool call, whether the agent remembers your rule or not.

What ThumbGate does

  • Sends are denied by default. The outbound-email-send gate in config/gates/default.json denies Gmail MCP send_message and send_draft, Gmail API messages/send calls made with curl or a client library, smtplib, sendmail and nodemailer transports.
  • Drafts stay allowed. create_draft, update_draft and list_drafts are not blocked, so the agent can still do the writing.
  • An approval covers one message. A send goes through only with an approval from a separately signed-in admin, bound to the digest of that exact action. It works once and expires after 15 minutes. An approval the agent writes for itself is rejected.
  • Other posting tools learn from a thumbs-down. If your agent posts somewhere ThumbGate does not cover by default, type "thumbs down" after it. ThumbGate turns that into a learned rule that warns when the agent makes the same call again, and blocks it in strict mode.

The tests for the email gate are in tests/gates-engine-outbound-email.test.js.

What ThumbGate does not do

  • It does not judge what a message says. It stops the send, and a person reads the draft.
  • It does not count or pace posts per platform. It is not a scheduler.
  • A learned rule matches the call you thumbed down, not its purpose, so a reworded call through a different tool is not caught.
