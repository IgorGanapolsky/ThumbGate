Pre-action gates for AI coding agents — air-gapped and GovCloud-routable.

Federal agencies are deploying AI coding agents (Claude, Copilot, Cursor, Codex) on classified and CUI workloads. ThumbGate is the gate engine that blocks known-bad tool calls before they execute — running entirely on-prem or inside AWS GovCloud / Azure Government, with the same enforcement core that ships in our public npm install thumbgate dev product.

What ThumbGate Federal is

Same engine, additive deployment profile. Not a fork, not a rewrite, not a rebrand.

The same gate engine

Captures thumbs-up / thumbs-down feedback from agent runs, promotes to a local lesson DB, and synthesizes pre-action gates that block known-bad tool calls (file writes, shell commands, network requests, force-pushes) before they execute.

The same MCP surface

gate_stats, recall, capture_feedback behave identically whether a developer runs ThumbGate on their laptop or inside an air-gapped GovCloud VPC. Same tool contracts, same response shapes.

Air-gapped deployment

Runs without outbound network access. Lesson DB is local SQLite + FTS5. Vector index is local LanceDB. No SaaS dependency, no Anthropic API call required at runtime when paired with a self-hosted reranker.

GovCloud LLM routing

Routes reranker and synthesis calls through Bedrock GovCloud (Claude on AWS GovCloud) or Azure OpenAI Service for Government when THUMBGATE_DEPLOY=gov is set. Replaces the default Claude reranker without touching the public package.

What ships in the public product vs. what's federal-gated

ThumbGate's public/Core architecture exists exactly for this kind of dual-market split. The dev product keeps shipping under our regular release cadence — federal features land in a licensed Core layer that's only reachable under THUMBGATE_DEPLOY=gov.

NIST 800-53 control coverage (target)

Pre-action enforcement maps naturally to several control families. Full mapping document and SSP contributions delivered as part of pilot engagement.

  • AC-3Access enforcement (gate blocks unauthorized tool calls before execution)
  • AU-2 / AU-12Audit generation (every gate decision logged with input, decision, justification)
  • CM-3Configuration change control (rule synthesis is the change record)
  • SI-7Software / firmware integrity (gate prevents agent from modifying disallowed paths)
  • SI-10Information input validation (gates run against tool-call payload before dispatch)
  • IR-4Incident handling (thumbs-down captures incident; prevention rule synthesizes mitigation)
  • RA-5Vulnerability scanning (lesson DB serves as known-failure corpus)
  • SR-3Supply chain protection (gate engine can block npm install / pip install of disallowed packages)
