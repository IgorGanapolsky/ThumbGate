How we counted, and what this does not show

  • Source. ThumbGate's own local logs for our agents: the gate event log, the audit trail and the agent registry. The counts come from scripts/build-monthly-report.js and the published 2026-11.data.json.
  • Sessions, not agents. An "agent session" is one ThumbGate server start by one of our agents. The same agent restarting counts again, and we cannot separate distinct agents from restarts, so we do not state a fleet size.
  • Small sample. One operator, one machine, 34 stopped or flagged actions. Do not read the percentages as industry rates.
  • Private by design. Only counts by rule and tool are published. No commands, file paths, messages, project names or customer data.
  • Strict mode. By default ThumbGate warns on matching destructive actions and denies detected secret exfiltration and gate-bypass attempts; strict mode (THUMBGATE_STRICT_ENFORCEMENT=1) hard-denies the rest. We did not break the counts out by mode.
