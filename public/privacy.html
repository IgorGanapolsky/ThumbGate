Privacy & Data Handling

What ThumbGate stores, where it lives, and exactly how to delete it. Last updated 2026-07-30.

Where your data lives by default

ThumbGate runs locally. Feedback, lessons, gate decisions, proof artifacts, context packs and audit records are written to ~/.thumbgate and your project files on your own machine. There is no account, no upload step, and no remote index in the default configuration.

The hosted tier

If — and only if — you configure an API key against the hosted endpoint (thumbgate-production.up.railway.app), feedback signals, memory entries and related workflow metadata are stored server-side and associated with that API key. Self-hosted installs never contact it.

Optional CLI telemetry is best-effort and covers install and usage metadata used to understand adoption and failures. Disable it with THUMBGATE_NO_TELEMETRY=1.

What is stored

  • Feedback signals (thumbs up / thumbs down) with the context you provide
  • Promoted memory entries and the lessons derived from them
  • Prevention rules generated from your feedback
  • Conversation excerpts, but only via the two tools named below

Conversation excerpts — stated plainly

Two MCP tools accept raw conversation excerpts — not summaries — and what they receive is stored alongside the feedback entry, so a lesson can be attributed to the action that earned it.

ToolWhat it receives
capture_feedbackchatHistory / conversationWindow: raw prior messages. An auto-capture path may include up to 8 preceding entries.
reflect_on_feedbackthe last 5–10 conversation turns.

This list is generated from the running server, not maintained by hand — see config/directory-manifest.json. A continuous integration test fails if a tool starts accepting conversation data without this page being regenerated.

No other tool receives conversation content. Gate evaluation sees the pending tool call (for example a shell command or file path), not your chat.

How to view everything stored

thumbgate dashboard          # browse feedback, lessons, gate decisions
GET /v1/search?q=*            # same data as JSON
ls ~/.thumbgate               # the raw files, plain JSONL

How to delete it

# delete individual entries
#   dashboard -> select entry -> delete

# delete all captured feedback and derived lessons
rm ~/.thumbgate/feedback-log.jsonl ~/.thumbgate/memory-log.jsonl

# delete everything ThumbGate has ever stored on this machine
rm -rf ~/.thumbgate

Deletion is immediate and local. Because storage is local by default, there is nothing for us to delete on your behalf — and nothing we could retain if you asked us to.

What we never collect

  • No source code is uploaded, indexed, or sent anywhere by the local gate.
  • No training on your data. Captured feedback trains only the local model on your own machine.
  • No telemetry of your commands. Website analytics (Plausible) are cookieless and cover the marketing site only, not the CLI or MCP server.

Sharing and retention

We do not sell customer data. Hosted data is used to operate the service and is not shared with third parties beyond the infrastructure providers required to run it. Local data is retained until you delete the files — see above. Hosted data is retained while the API key remains active, or until you request deletion, subject to operational and legal retention requirements. To delete hosted data, email igor@igorganapolsky.com.

Secrets

ThumbGate scans captured feedback for credential patterns and redacts them before writing. This reduces, but cannot eliminate, the chance of a secret appearing in a stored excerpt — treat ~/.thumbgate with the same care as your shell history.
