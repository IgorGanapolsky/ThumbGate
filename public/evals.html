First-of-its-kind evals for pre-action enforcement

Every layer of the ThumbGate enforcement stack ships with a measurable eval.

If the gate doesn't have an eval, it's a guess. Each lane below is a real artifact in this repository — you can read the JSON, run the script, and reproduce the number. Nothing here is marketing math.

1. Deterministic pre-action benchmark — bench/thumbgate-bench.json

Ten ground-truth scenarios across seven services (github, sqlite, filesystem, npm, railway, shell, git). Each scenario specifies a tool call and an expected decision; ThumbGate's evaluator must reproduce the decision byte-for-byte. The bench is intentionally small and deterministic so a regression is unambiguous.

2. ProgramBench-style cleanroom smoke lane — bench/programbench-smoke.json

Three whole-repo clone tasks adapted from the ProgramBench methodology. Each task spins up an isolated working tree, runs ThumbGate against a real edit sequence, and verifies the gates fire without leaking state between cleanroom runs. Not an official ProgramBench score — a smoke lane that proves the gate works against real repo-scale workflows.

  • 3 cleanroom tasks
  • Run command: npm run thumbgate:bench:programbench
  • Documented at docs/THUMBGATE_BENCH.md

3. Prompt evaluation suite — bench/prompt-eval-suite.json

Six prompt evaluations against expected outputs, gated by an explicit success-criteria block. Methodology mirrors Anthropic's published prompt evaluation guidance: test against expected answers, compare versions, review outputs for errors.

4. RLAIF judge reward — scripts/judge-reward-function.js

The reward signal used to align ThumbGate's lesson-promotion behavior. The judge scores agent outputs along separately-tracked dimensions (safety, helpfulness, calibration, evidence) and produces a single scalar reward per step. The reward function is auditable — every block decision in production carries the rule that fired, the evidence that triggered it, and (when applicable) the judge score.

Per-step scoring is durable: every check decision (block / approve / log) becomes a DPO or KTO training signal exportable via npm run feedback:export:dpo for fine-tuning your local model on what your team actually wants.

5. Bayesian conversion-rate analysis — scripts/conversion-rate-stats.js

Beta-binomial posterior with credible intervals for every funnel surface — useful when comparing two CTAs, two checkout copy variants, or two prevention-rule promotion thresholds. The Bayesian A/B harness (scripts/ab-experiment-framework.js) layers on top: deterministic SHA-256 variant assignment, MC-sampled posterior decision rule, practical-significance threshold (default 5% relative), and loss-bound stopping criterion. Verdicts: ship_a | ship_b | inconclusive_stop | continue.

  • 24 unit tests in tests/conversion-rate-stats.test.js — pin the posterior parameter math, credible-interval bounds, and U-shaped Beta mode handling.
  • 11 unit tests in tests/ab-experiment-framework.test.js — variant assignment determinism, weight calibration, decision correctness under clear-winner / tied-at-scale / low-sample regimes.

6. Adapter compatibility proof lanes — scripts/prove-adapters.js

Each supported agent runtime (Claude Code, Cursor, Codex, Gemini CLI, Amp, Cline, OpenCode) has a dedicated proof lane. The lane installs ThumbGate against the runtime's current hook/plugin API, fires a known-bad tool call, and verifies the block. When a runtime ships a breaking change, the lane goes red and we know within a CI cycle — not after a customer reports it.

  • 4 adapter proofs + automation proof suite (scripts/prove-automation.js)
  • Run commands: npm run prove:adapters · npm run prove:automation

7. Whole-suite gating — npm test

Every release pushes through the full test chain before it ships to npm or Railway. The chain is brittle on purpose: a single failing assertion blocks the deploy. This is the floor — bench, prompt eval, conversion-rate math, and adapter proofs all sit on top.

Why the evals matter for the buyer, not the engineer

An AI agent governance product without evals is a credibility problem. The Agent Manager owning CLAUDE.md, the plugin marketplace, permissions policy, and which skills ship cannot rely on a vendor that promises enforcement without proving it. The evals above are how the buyer verifies, before purchase, that the enforcement layer they're about to put underneath their agent runtime is real.

"First-of-its-kind benchmark for AI memory systems that reason about user track records" is the bar for advice-quality calibration. ThumbGate's bar is the same idea applied at the tool-call boundary: every gate decision is gradeable, every block is reproducible, every adapter is proven against the current runtime.

Run the evals yourself. The bench files live in bench/; the proof scripts live in scripts/prove-*; the test suite is wired into npm test. Nothing here requires a hosted account.
