## Default posture

Do not oversell enterprise maturity. The strongest honest posture is:

> ThumbGate is early, but the pilot is intentionally scoped so GT does not have to trust our hosted infrastructure with client data. The enforcement path runs locally, the demo uses synthetic fixtures, and the pilot deliverable is evidence: which legal AI actions were blocked, warned, allowed, or routed to attorney review.

## Seven answers to rehearse

### 1. SOC 2 status

**Answer to use if asked:**

> We are pre-SOC 2. I do not want to imply otherwise. That is why the proposed pilot is local-first and no-client-data: the enforcement hook, lesson DB, and gate evaluation run inside the firm's environment. For a production hosted rollout, SOC 2 or an equivalent contractual/security review becomes part of the next phase.

**Do not say:** "SOC 2 is in progress" unless there is an auditor, date, and scope already committed.

### 2. BAA / HIPAA

**Answer to use if asked:**

> We have not executed a BAA with a customer yet. The pilot architecture is designed to avoid PHI egress: local enforcement, synthetic fixtures, and no client documents required. If GT wants to test a health-care-client workflow later, we would handle BAA language through mutual legal review before any PHI enters scope.

**Do not say:** "BAA-ready" as a blanket claim. Say "architecture can be scoped to avoid PHI during the pilot."

### 3. Data retention and model training

**Answer to use if asked:**

> The pilot should not send client content to ThumbGate. The local gate can evaluate tool calls and produce audit events inside GT's environment. Any hosted component should receive only counters, rule metadata, or synthetic/demo data unless GT explicitly approves otherwise. We do not need firm data to train a model for this pilot.

**Follow-up proof to show:** `bash scripts/demo/zero-egress-proof.sh`.

### 4. IP and hallucination indemnity

**Answer to use if asked:**

> ThumbGate does not generate legal advice; it gates actions proposed by an agent or model. I am willing to discuss standard IP indemnity for ThumbGate's own software in a paid pilot agreement, subject to counsel. I would not offer blanket hallucination indemnity for outputs generated by third-party models. The point of the pilot is to reduce that risk with deterministic controls and audit evidence.

**Do not say:** "We indemnify hallucinations." That creates the wrong liability box.

### 5. Pilot price

**Answer to use if asked:**

> The 30-day pilot range is $2,500 to $7,500 flat, depending on scope. For a first call, I would propose the narrow version: one intake workflow, synthetic adverse-party fixture, one approved disclaimer/routing policy, local-first gate proof, sample audit export, and a go/no-go rollout recommendation.

**If asked for a number today:** say **$2,500 for the narrow no-client-data pilot** and reserve higher scope for integrations or additional workflows.

### 6. Post-pilot commercial model

**Answer to use if asked:**

> I would not ask GT to buy a broad seat rollout off this call. If the pilot works, the next step is a scoped Team rollout for one practice area or one agent surface. Pricing would depend on how many runtimes, reviewers, and evidence-retention requirements are in scope. The self-serve Pro plan is not the GT buying motion.

**Do not lead with:** `$19/mo` or GitHub checkout. That is the wrong buyer path.

### 7. Procurement/security packet

**Answer to use if asked:**

> I can send a concise security and architecture packet after the call. I would rather keep the first meeting focused on whether the control pattern is useful: preloaded ground truth, pre-action blocks, attorney review, and reproducible audit evidence. If that lands, we can tailor the procurement packet to GT's actual pilot scope instead of pretending a generic questionnaire answer is enough.

## The ask

End with this:

> Would you be open to a narrow no-client-data pilot: one intake workflow, one approved disclaimer/routing policy, one synthetic adverse-party fixture, and one audit export format? If yes, the next step is a 30-minute technical scoping call with whoever owns AI/security review.

## What not to do

- Do not pitch Stripe checkout.
- Do not claim SOC 2, HIPAA, GDPR DPA, BAA, FedRAMP, carrier discounts, or guaranteed malpractice prevention.
- Do not quote made-up malpractice dollar exposure.
- Do not ask for client data.
- Do not say the public CLI is the whole enterprise product. The enterprise value is the governed pilot, policy pack, approval workflow, audit proof, and rollout support.
