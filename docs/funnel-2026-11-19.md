# ThumbGate funnel, last 14 days (read 19 Nov 2026, about 1:40 PM)

Question: people install it, nobody pays. Where does the funnel stop? Every number below comes from a query run on 19 Nov 2026; the query is named next to it.

**Window limits, stated first.** npm and Stripe cover the full 14 days (5 to 18 Nov for npm, 5 to 19 Nov for Stripe). The hosted telemetry store does not: its oldest row is 16 Nov 2026 at 4:32 PM, so it covers about 3 days. The hosted funnel-event stream is capped at 10,000 rows and its oldest returned row is 12 Nov, so it is truncated. Anything below marked "3 days" is not a 14-day figure.

## What the funnel says

1. **The top is fine and the bottom is empty.** About 1,400 real visitors in 3 days and 2,517 downloads in 30 days, then 84 reach the checkout step, then none confirm it since the human-click gate went live. The loss is between "viewed the checkout step" and "confirmed it", and before that between "installed" and "ever blocked something".
2. **We cannot see install to first block.** 1 init and 4 first-block events (possibly one install) against 1,401 downloads. Until the CLI reports more, nobody can say whether users never hit a block or never report one. The first-block upgrade line added in this change makes that moment visible to the user; it does not fix the measurement gap.
3. **The old "76 checkouts" was mostly crawlers.** Stripe created a session when a crawler opened a payment link, and none of those sessions recorded a user agent. Since the human-click gate (18 Nov, 7:04 PM, live build `3fabf08d3` per `/health`), Stripe has created no session with a browser user agent.
4. **Open question, not answered by this data.** After the gate, 0 real visitors confirmed the interstitial. That is either no buying intent or a gate that stops real buyers. Telling those apart needs a headless-browser test of the confirm click, and that click creates a live Stripe session, which the Stripe rule forbids outside test mode. Not run.

## Data quality

- Crawler filter used here: the event's own `isBot` / `isBotTraffic` flags, plus the user-agent patterns in `scripts/bot-detection.js`. CLI events send an empty user agent, so they were judged by their own flags (`audience`, `isInternal`, `isTest`), not by user agent.
- Hosted billing summary 30-day visitors (14,647) exceed hosted lifetime visitors (1,198): lifetime counters were reset. Do not quote lifetime figures.
- The summary's `ctas.checkoutStarts` (217 over 30 days) counts older, pre-gate starts and is not a count of people.
- Not queried: Plausible, GitHub traffic, Zernio, and telemetry from other machines.

## What changed with this note

- `scripts/checkout-session-count.js` counts checkout starts without crawlers: only sessions the human-click gate stamped `uaClass = browser`, with owner and internal sessions out and the pre-gate sessions reported as their own bucket. The board number "checkouts 7d started" should read from it.
- `scripts/first-block-upsell.js` prints one plain upgrade line on the first real block, then at most once per 7 days. Details and tests are in the commit.
