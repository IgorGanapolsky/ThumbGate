# Owner-only administration

## Problem

Igor needs one private, read-only view of ThumbGate customers, subscriptions, payments, refunds, prices, hosted data, analytics, and runtime health at `/admin`. Production currently returns 404. A separate unfinished admin implementation exists in the shared checkout but is not on main. It uses a separate login and write operations and does not satisfy this brief.

ONE Thing: the owner signs in through the existing Apple/session flow, opens `/admin`, and sees current records with provenance. Everyone else receives 404, including authenticated customers. Finish requires behavioral tests, fresh EGM review, hooks, a PR, `npm run pr:manage`, and after protected merge a matching production build SHA and anonymous 404. No bypass of review requirements.

## Technical Plan

### Access boundary

Add the admin dispatcher near the start of `createApiServer`, before public routing, CORS, project-path selection, generic authentication, and tenant path resolution. Match `/admin`, `/admin.html`, all `/admin/` descendants and `/v1/admin` descendants. Decode pathname safely so encoded aliases cannot enter public file serving. Invalid paths deny.

Resolve only the existing `thumbgate_auth_session` cookie with a non-provisioning identity reader over the same hashed durable session store. Do not use `getPaidAuthSessionEntry`, whose hydration can provision keys and prune storage. Read durable authority on each request, including warmed-cache requests; expiry or missing record denies without writing. Require an unexpired server-issued session with a recognized SSO provider and `ssoEmail` matching `isConfiguredOwnerEmail`, which uses only `THUMBGATE_OWNER_EMAILS`. Re-evaluate the allowlist on each request. Never infer ownership from plan, API key, query parameters, headers, client email or a hardcoded address. Empty allowlist denies everyone. No alternative login endpoint. Existing Apple login remains the entry; an anonymous `/admin` must not redirect or disclose it.

Denied page and API requests use the same generic 404 response, including HEAD and OPTIONS, with no admin hint or authentication challenge. Set `Cache-Control: private, no-store`, `Vary: Cookie`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`, and `X-Content-Type-Options: nosniff`. Do not enable cross-origin admin reads. Allowed methods are GET and HEAD only. An owner write request receives 405 without invoking a provider. Unknown owner routes receive 404. Assets are embedded in the protected HTML; no publicly served admin data or scripts.

### Module and data shapes

`scripts/owner-admin.js` owns read-only collectors. Route registry: `overview`, `stripe`, `data`, `analytics`, `observability`. A section returns `{status: 'ok'|'partial'|'unavailable', generatedAt, source, data, warnings}`. Errors contain fixed codes, never provider messages, credentials or customer details. No global response cache. Every call authorizes before collecting. Provider calls have deadlines; failed sections remain visibly unavailable rather than reporting zero.

Usage sketch: server dispatch validates owner, then calls `collectAdminSection(section, {feedbackDir, buildMetadata, runtime, ...trustedDependencies})`. The server supplies the unmodified global feedback root, never a request-selected path. The existing trusted tenant resolver remains unchanged. The route runs before tenant scope. The release branch integrates tenant-isolation head `07eb863e938f286ef0a3bc7df780876ac9ceba9b`. Global owner root resolution and the authorized collector run inside `withoutDataScope`; the existing frozen customer context is restored afterward. A per-server WeakSet prevents duplicate runtime observation when private routes recurse under tenant scope. The cross-tenant reader never weakens customer APIs or accepts tenant roots from the browser.

Stripe uses only the existing production server `STRIPE_SECRET_KEY` and the installed Stripe SDK. Reuse/export the existing `billing.getStripeClient` so account configuration cannot diverge. GET-only collection endpoints for subscriptions, customers, charges, refunds, products, and prices. Paginate each resource with a validated opaque Stripe `starting_after` ID and a bounded page size. Expose `hasMore` and next cursor, with Load more controls so all records are reachable. Sanitize each returned object to named fields only. Subscription fields include status, customer, plan/price, currency, amount, renewal date and cancellation status. Customer names and email may appear only in the protected response/UI. Payment/refund fields include provider ID, amount, currency, status and timestamp. Products/prices include active state and recurring interval. Use Stripe dashboard links for changes; no refund/cancel/edit buttons or mutation API.

Mark test-mode and internal/owner records using the existing billing/revenue classification plus metadata and the configured owner allowlist. Evaluate all receipt, billing, metadata and expanded-customer email evidence; any internal evidence wins over external evidence. Persist that evidence in reconciled events, union it during ledger reconciliation, and never erase a known ledger identity with a missing live email. Do not count those purchases as external revenue. Keep currency amounts separate. Reuse `getBillingSummaryLive` or its existing batch implementation used by `/v1/billing/summary`, `npx thumbgate cfo` and revenue-status. Do not calculate a competing revenue metric from the paginated lists. Reuse telemetry/dashboard visitor, checkout, signup and funnel aggregators. Return only an explicit summary projection to avoid returning hidden key stores or raw telemetry.

Hosted data uses durable account/key/session/activation sources already used by the server. Deduplicate accounts by stable customer identity; session counts are not signup counts. Reuse canonical `hashDataIdentity` partition mapping rather than inventing one. Read each tenant's feedback and promoted lesson records with bounded, read-only readers, reporting missing or truncated sources as unknown/partial. Never expose API keys, session tokens, raw feedback text, logs, local paths or full key-store records. Names/emails only in owner responses. Include unattributed legacy data separately instead of assigning it to a customer. Project grouping is conditional on the project-scoped dashboard contract; show unavailable until that feature lands, and integrate its trusted project IDs after landing.

Observability includes the same version/buildSha/uptime fields as `/health`, process start time, deployment ID/commit from Railway environment when present, disk usage via `fs.statfs`, and recent server error summaries. Add a bounded in-memory ring for HTTP 5xx responses with only timestamp, status and a fixed route category, never raw URL, query, body, headers or error text. Clearly label its process-lifetime retention and reset behavior. Count successful telemetry ingests in rolling one-second buckets and show events/minute with observation start, without retaining payloads. Unknown deployment time is explicitly unavailable; process start is never labelled deploy time.

### Exact collection contracts and limits

All API responses are JSON. Monetary display uses formatted currencies with Stripe charge exponents, including ISK/UGX compatibility rules and zero/three-decimal currencies. Recurring labels include interval_count (for example, Every 3 months). Integer minor units remain unchanged in the API. GET `/v1/admin/overview` returns health and section availability without eagerly calling Stripe. GET `/v1/admin/stripe/{customers,subscriptions,payments,refunds,products,prices}` lists one resource. GET `/v1/admin/stripe/subscription-items?subscription=sub_...` lists every item for a validated subscription using the same bounded pagination and an `si_` cursor. Each subscription row links to this protected item view, including when its embedded list is incomplete. Payments use charges, not payment intents, so settlement/refund state is visible. Query `limit` defaults to 25 and ranges from 1 to 100; `starting_after` is empty or an ASCII Stripe ID of at most 128 characters with the resource prefix. Reject duplicate or unknown query parameters with owner-only 400. HEAD performs authorization and route validation but no collection and returns no body. GET `/v1/admin/data` returns current known accounts with bounded counts. GET `/v1/admin/analytics` returns the existing 30-day billing summary's explicit funnel, signups, revenue, trafficMetrics, attribution and data-quality fields. GET `/v1/admin/observability` returns safe runtime fields. No arbitrary path/window/provider selector.

Stripe amounts remain integer minor units with currency, never combined across currencies. Common fields are id, created, livemode and classification. Customers add name/email, subscriptions add customer/status/items and current_period_end or item-level period ends, with status: all including canceled/trialing and all line-item prices, charges add customer/amount/currency/paid/status/amount_refunded, refunds add charge/amount/currency/status, products add name/active, prices add product/active/unit_amount/currency/recurring. Classification is internal, test, external or unknown; absence of customer evidence is unknown. Do not expose provider metadata except classification flags. Limits are 8 seconds per provider request, zero SDK retries, at most two concurrent provider requests; the page lazily loads resources. SDK errors return a fixed unavailable code.

The shared billing batch collector will add optional reconciliation diagnostics alongside the existing summary, distinguishing ok/empty, timeout, unavailable and unconfigured. Preserve calculations and existing callers. The admin projects selected aggregate fields recursively through a finite schema, excluding record-level events, customer identities and raw errors. Failed reconciliation makes analytics partial with ledger provenance, never authoritative live zero. Tests cover provider rejection and deadline separately.

For data, read `api-keys.json` and `auth-sessions.json` from the trusted root directly using guarded read-only IO; do not call key provisioning or migration loaders. Parse at most 8 MiB per JSON source, require valid object shapes and report corrupt/missing stores. Keys deduplicate by customerId. SSO sessions with customerId join that account; remaining verified SSO emails use the existing canonical free-account hash. Map a free identity to a paid customer only through exact normalized stored email evidence, otherwise keep unknown/possible duplicate labels. Count only unexpired sessions as current accounts and label coverage as current known accounts, not lifetime signups. Expose hasActiveKey separately from hasCurrentSession. If neither account inventory source is usable, return unavailable with no data. If only one is usable, expose totalKnown as a lower bound, total as null, and inventoryComplete as false. Use the existing signup analytics metric independently. No migration/backfill.

Count feedback-log.jsonl and memory-log.jsonl with streaming read-only IO, capped at 16 MiB or 100000 records per file and 2 concurrent files. Return total, complete, malformedLines and source state. Missing tenant directory means no hosted data; missing file inside a directory is unknown, never a claimed complete zero. Account inventories use stable identity ordering and opaque offset cursors; each page maps/counts at most 50 accounts, and pagination remains reachable beyond 500 accounts. JSON source size is capped at 8 MiB, with explicit unavailable state above that bound. Canonicalize the server-trusted root once (including macOS system aliases), then inspect tenants/partition/file containment and reject every symlink component below that root. Read global legacy files only in a separately labelled unattributed section. No feedback or lesson body enters a response. Customer display fields use explicit string limits. Canonical partition/hash functions are injected from the server, never copied.

Runtime errors retain the last 100 HTTP 5xx summaries. Telemetry keeps 60 one-second buckets and reports successful persisted events across the current second and previous 59 seconds, with explicit window start and one-second precision; increment only after appendTelemetryPing succeeds. Report the exact observation duration if startup is less than one minute ago. Test persistence failure, bucket expiry and ring eviction. Filesystem stats expose numeric capacity/free/used only.

Release integration gate: tenant-isolation must land or be integrated into the reviewed branch before production release. Against that exact baseline, prove owner cross-tenant counts, customer A/B isolation and rejection of request-controlled roots. Project counts remain conditional until the project feature lands; refresh its contract before final release. The builder must not copy another agent's uncommitted scope implementation.

### Goldfish corrections and design decision

Financial correctness is owned by billing. Add classification evidence to reconciled and ledger revenue resolution, and expose shared external-revenue totals by currency plus internal/test/unknown exclusions. Preserve existing broad accounting totals for backward compatibility and label them separately; admin headline uses only the shared classified external totals. Resolve owner evidence from configured owner allowlist and existing classifier, test status from livemode and synthetic metadata, and deduplicate with existing provider order identity. Missing evidence remains unknown, not external. The same shared summary fields are available to CFO/revenue-status; the admin never recomputes them. Include historical owner purchases, synthetic/test records, missing identity, cross-provider duplicates and mixed-currency fixtures. Reconciliation diagnostics include completeness when capped charge/price lists report has_more. No full live summary claim on incomplete source.

The admin auth reader consults the hashed durable session authority without key restoration, expiry cleanup, cache insertion or writes. Match only verified provider names used by the existing callback. Any malformed/oversized session store fails closed. Add tests asserting unchanged storage for denied cold-cache and expired requests and denial after durable deletion with a warmed cache. Inform the tenant/auth owner of this narrow adapter before editing; preserve their resolver.

Admin collection has a process-wide cap of two active requests and a response cap of 1 MiB. A separate billing-owned two-slot provider semaphore wraps actual SDK promises for both admin lists and shared reconciliation. A response deadline or client abort never releases a provider slot until that underlying request settles; new attempts fail closed while both slots remain occupied. Refuse excess owner collection requests with fixed 429; do not disclose this gate to non-owners. Data pages default 25/max 50 accounts, with an opaque validated cursor. Limit canonical scrypt mapping to the current page and yield between mappings so health requests continue. Abort streaming at limits; honor cancellation/deadlines before the next file/provider call. Provider calls use per-request SDK options, avoiding global factory configuration changes. Analytics scans use the same billing read-path resolver as the real JSONL and key-store loaders, including enabled legacy ledger merging, legacy trial-email fallback, telemetry sources and session/workflow stores. Check size and trusted-root containment for every selected source; return unavailable when shared synchronous readers would exceed the 8 MiB source budget. Resource list calls remain separately usable. A 10-second total section deadline must stop future calls and cancel active streams; a timed-out shared reconciliation must not start later Stripe calls. These behaviors are tested under concurrent refresh and slow-provider fixtures.

Stripe list status parameters include all subscriptions and both active/inactive products/prices. A payment row is a charge, showing amount_refunded separately; refunds are separate records linked by charge ID. Multi-item subscription prices remain item arrays. Current accounts can carry both verified free and paid partitions after an exact stored-email join; count each partition once, retain ambiguous identities separately, and label current-known coverage. This does not migrate any data.

Architecture comparison: the independent design reviewer proposed domain-owned billing/data read models composed in the server. The readiness reviewer preferred a collector module. Select a thin collector module for pagination, field projection and independent source states, while billing retains classification/reconciliation and the server retains canonical identity and session authority. This keeps one private API contract without a second financial definition. No cross-model performance claim is made.

### UI and verification

Replace only this branch's `public/admin.html` with an accessible responsive private dashboard. Tables show explicit empty/loading/unavailable states, collection timestamps and pagination controls. Render untrusted strings using textContent; no provider HTML or external analytics. CSP permits only the required same-origin resources and embedded script/style hashes or nonce. Browser fetches use same-origin cookies. Logout uses the existing session endpoint. A normal owner session can navigate to `/admin` after existing sign-in without an extra credential prompt.

Tests use generated synthetic identities only, never real customer names/emails or production credentials. Exercise the actual HTTP server: anonymous, non-owner SSO, owner SSO, expired/revoked sessions, empty/removed allowlist, static admin/operator keys, forged identity headers, path aliases and all methods. Denied requests must perform zero collector/provider calls. Test pagination, internal/test flags, mixed currencies, unavailable providers, XSS payloads and no secret fields in responses. Verify no filesystem writes from collectors. Test actual headless Playwright Chromium owner and denied journeys using isolated synthetic local data first; never use BrowserOS, CDP 9118, Google Chrome or OS automation. Production identity/session proof must remain private.

Rollout: commit scoped files with hooks; open PR and run manager. Configure allowlist only if missing and verified from the owner's existing account; Railway CLI readback prints variable name only. Preserve required coordination logs. No auth setup or spending. After protected merge, verify provider commit, `/health` buildSha, owner journey and anonymous curl 404. Rollback is normal protected revert; missing allowlist fails closed.

Throughput checkpoint: blocking steps are spec and fresh EGM review; the builder owns all coupled implementation files in the isolated worktree. Reviewers read independently and never edit. Shared mutable state is limited to the coordinated report line and provider configuration. One builder is the smallest safe decomposition because auth, collectors and UI share one contract.

## Alternatives Rejected

1. Reuse the unfinished shared admin password/login and mutation APIs. It does not use verified Apple session identity, exposes a separate login and exceeds the read-only scope.
2. Put collectors inline in the large API server. It avoids a module but makes field sanitization, pagination and provider-failure tests harder to audit. A single collector module with a small route adapter centralizes the private response contract.
3. Build a separate admin service or proxy Stripe through the browser. This duplicates sessions/deployment or exposes provider access. Existing server and SDK are sufficient.
4. Copy CFO analytics. That would make internal/test exclusions and revenue definitions diverge. Reuse the existing production summary implementation.
