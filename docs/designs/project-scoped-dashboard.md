# Project-scoped dashboard

## Problem

ThumbGate users need one account containing many projects. Each project must own its feedback, lessons, gate decisions, tool/agent activity and exports. The current package-name/basename scope in [project-scope.js](../../scripts/project-scope.js) can collide; the dashboard aggregates histories. A selection must never broaden account access.

ONE Thing: implement stable project attribution and verify two projects in one account stay separate through capture, enforcement, dashboard, lessons and export.

Finish condition: same remote across clones resolves to one key; different remote repositories resolve to different keys; all project B API responses exclude A records and derived counts; global gates remain visible and labelled; project-only gates cannot fire elsewhere; migration preserves row counts and malformed lines; headless Playwright Chromium can switch projects with the selection reflected in the URL. Production completion additionally requires protected merge, matching /health buildSha and /dashboard?project=... HTTP 200.

The tenant audit in the main checkout .herdr-report.md reports shared production writes. The independently owned fix/hosted-tenant-isolation is a release dependency. Preserve fix/dashboard-dead-ui and PR 5062. Do not sync local private histories to production.

## Technical Plan

### Data shape and identity

Add scripts/project-identity.js. A project descriptor is `{ projectKey, projectName, identitySource }`; records carry it at top level. `scope.projectId` remains the legacy label for compatibility. `projectKey` is `repo_` plus full SHA-256 of a canonical remote identity, `local_` plus full SHA-256 of machine identity and canonical repository root for remote-less repositories, or `unassigned`. Hashes have negligible collision risk, not a mathematical guarantee. Remote-less repositories cannot share identity across machines without a remote.

Canonical remote identities remove credentials, query, fragment, trailing slash and `.git`, collapse SSH scp and HTTPS spellings, lowercase hostname, preserve generic repository path case, and case-fold GitHub paths. Preserve non-default service ports. Prefer origin, otherwise deterministic first remote. Resolve git worktrees through git metadata rather than directory names; resolve subdirectories to root. Use execFile with argument arrays and bounded timeout, never a shell. No persisted remote credentials, local paths or machine identifiers are returned in API labels. Machine fallback uses an existing OS machine identifier when available, with a persisted random local ID only when necessary. Resolution caches are bounded and invalidate when git configuration changes.

For live local capture, derive from execution cwd rather than trusting an arbitrary label. For hosted capture, preserve a validated incoming projectKey or resolve explicit remote metadata; never infer the hosted server checkout as the customer's project. Hosted cwd strings are not executed or read on the server. Invalid project keys return 400 at the API boundary. Project values are not path fragments.

Historical attribution precedence: existing valid key; explicit recorded remote; recorded scope.projectId. Historical cwd alone is insufficient because a directory can be reused; resolve it only when a recorded canonical remote corroborates its current remote, otherwise use recorded scope or Unassigned. A legacy scope identifier becomes `legacy_` plus SHA-256 of the exact identifier, labelled as legacy, unless a unique proven mapping to a remote key exists. Never merge unrelated repos by basename. Missing, placeholder or ambiguous evidence becomes Unassigned. Memory rows inherit the matching sourceFeedbackId's identity within the same account. Backfill never uses the migration process cwd.

### Writes and enforcement

Public module contract: `resolveLocalProject(cwd, options)` returns a descriptor; `projectForRecord(record, options)` is pure by default and never falls back to current cwd; `matchesProject(record, projectKey)` treats omitted key as All and unassigned literally; `gateAppliesToProject(gate, projectKey)` allows explicit/legacy static global gates and requires exact equality for project gates. `buildProjectCatalog(feedbackDir)` reads only the supplied root. Thread the descriptor through [feedback capture](../../scripts/feedback-loop.js), promoted memories, [lesson DB](../../scripts/lesson-db.js), [audit trail and agent registration](../../scripts/audit-trail.js), [telemetry](../../scripts/telemetry-analytics.js), [gate engine](../../scripts/gates-engine.js), [auto promotion](../../scripts/auto-promote-gates.js), [MCP](../../src/mcp/server.js), [hosted API capture](../../src/api/server.js), and [CLI context](../../bin/cli.js). Preserve it through the existing [Hermes sync](../../src/hermes-sync-plane.js) payloads. `/ingest` is the PostHog proxy, not feedback sync; do not misroute customer signals into it.

Gate definition scope is `global` or `project`, with projectKey required for project scope. Existing static gates remain global for compatibility and are labelled Global. Auto-promoted gates inherit source lesson identity and use project scope. Unknown legacy generated gates must not silently become global; keep them inactive/unassigned until attributable. Check applicability before matching, escalation, satisfaction or counting in both synchronous and asynchronous evaluators. Mutable gate satisfaction uses state.satisfiedByProject[projectKey][conditionId], including execution of global gates; old unscoped satisfaction applies only to Unassigned. `isConditionSatisfied(conditionId, {projectKey})` and `satisfyCondition(..., {projectKey, feedbackDir})` carry explicit context. Overrides/recurrence use projectKey in their digest and session key. Account state paths must come from the authenticated account root. Promotion grouping, generated gate IDs, regression samples and expiry/update matching all include projectKey; no summed thresholds across projects. Gate stats add per-project buckets without deleting lifetime counters. Record project keys on block/warn and audit records.

### Migration and validation

Add scripts/migrate-project-scope.js with dry-run default and explicit `--apply --offline`. Use the explicit JSONL store matrix: feedback-log.jsonl (descriptor/legacy scope), memory-log.jsonl (sourceFeedbackId inheritance), audit-trail.jsonl and gate-events-log.jsonl (descriptor/recorded scope; never infer current agent project), telemetry-pings.jsonl and telemetry-log.jsonl (descriptor/legacy scope), agent-registry.jsonl and observed-agent-registry.jsonl (descriptor/recorded project), diagnostic-log.jsonl and decision-journal.jsonl (descriptor/recorded scope). Inspect actual constants before finalizing filenames. Existing per-project subdirectories are enumerated inside each account, deduplicating canonical file paths; symlink escapes are refused. Non-JSONL gates: explicit project descriptor preserved, static gates global, generated source lesson inherits descriptor or remains unassigned/inactive. gate-stats.json legacy counters remain account totals and cannot be assigned to a repo. dashboard-review-state.json is upgraded to version 2 without attributing its baseline. SQLite lessons use matching sourceFeedbackId before legacy fallback. Existing SQLite primary IDs stay unchanged; new writes retain the logical ID in sourceRecordId and choose a project-qualified storage ID only if an incoming logical ID collides with a different project. Enumerate known JSONL signal files within a supplied account root and existing tenant subdirectories; never discover arbitrary home/repository directories. Stream every line, preserve malformed lines and unknown fields, resolve sourceFeedbackId only within its account. Print counts only (files, rows, attributed, unassigned, malformed, DB rows); no content, paths, emails or secrets. Dry-run must not mutate source roots, caches, machine IDs or source DB journals. SQLite inspection uses a private temporary copy of the DB and WAL, verifies source fingerprints before and after copying, delegates recovery to SQLite, and removes the temporary directory.

Apply requires `--offline` (or `offline: true` programmatically), and takes an exclusive migration lock. Stop all API, hook, MCP, CLI and background writers before using it; the flag acknowledges that maintenance prerequisite and does not stop them itself. Create a unique backup before atomic same-directory replacement; fsync and verify source stat identity has not changed before replacement, abort on concurrent modification. SQLite upgrades add projectKey/projectName columns and indexes transactionally, without dropping tables or rebuilding IDs; keep FTS triggers and row counts. Backfill DB attribution by sourceFeedbackId from the account's source log, otherwise Unassigned. The migration manifest records per-file original fingerprint, backup path, replacement checksum and completion. A retry skips replacements whose checksum matches, refuses externally changed files, and resumes remaining files then SQLite; no destructive rollback is automatic. SQLite DDL and all backfill rows share one immediate transaction; an interruption rolls both back, while completed JSONL replacements remain tracked for retry. No source-root mutation is needed for normal dashboard use: read-time attribution remains active before and after migration. Restoring backups is a separately authorized offline operator action. A legacy alias maps to a canonical key only when a record contains both that exact alias and a valid canonical descriptor, and all such records in the same account agree; conflicting aliases remain legacy. Retry is idempotent. Existing histories remain readable before apply through the same pure attribution function. On hosted volume run counts without exporting data; do not run a rewriting migration against active writers.

Tests use temporary synthetic accounts/repositories only. Cover SSH/HTTPS remote equality, nested paths/worktrees, different owners same basename, credential stripping, remote-less machines, legacy aliases/Unassigned and ambiguous mappings, idempotent migration with malformed rows and source changes, SQLite data/FTS preservation, interleaved tenant/project requests, scoped stats/search/detail/export/SSE, DPO no cross-project pairing/distractors, both gate evaluators, and headless Playwright switcher navigation. Run existing affected tests and required repository checks with hooks. Missing legacy verification commands are reported honestly; do not recreate obsolete harnesses merely to obtain a pass.

## Alternatives Rejected

- Package names and directory basenames cannot identify repositories uniquely.
- Moving source histories into project subdirectories would break legacy readers and require risky dual writes.
- Temporary filtered copies per HTTP request add IO, sensitive copies and snapshot races.
- Filtering finished responses leaves cross-project aggregate counts and ranking leaks.
- AsyncLocalStorage or a global current-project variable hides dependencies; explicit query options are reviewable.
- Rewriting online JSONL while writers append can lose data. Keep migration offline and support read-time attribution until maintenance.
