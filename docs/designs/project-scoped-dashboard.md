# Project-scoped dashboard

## Problem

ThumbGate users need one account containing many projects. Each project must own its feedback, lessons, gate decisions, tool/agent activity and exports. The current package-name/basename scope in [project-scope.js](../../scripts/project-scope.js) can collide; the dashboard aggregates histories. A selection must never broaden account access.

ONE Thing: implement stable project attribution and verify two projects in one account stay separate through capture, enforcement, dashboard, lessons and export.

Finish condition: same remote across clones resolves to one key; different remote repositories resolve to different keys; all project B API responses exclude A records and derived counts; global gates remain visible and labelled; project-only gates cannot fire elsewhere; migration preserves row counts and malformed lines; headless Playwright Chromium can switch projects with the selection reflected in the URL. Production completion additionally requires protected merge, matching /health buildSha and /dashboard?project=... HTTP 200.

The tenant audit reported shared production writes. Tenant storage isolation (PR #5066) and dashboard UI fixes (PR #5065) are now merged and integrated into this candidate; their behavior is preserved. PR #5062 remains separate. Do not sync local private histories to production.

## Technical Plan

### Data shape and identity

Add scripts/project-identity.js. A project descriptor is `{ projectKey, projectName, identitySource }`; records carry it at top level. `scope.projectId` remains the legacy label for compatibility. `projectKey` is `repo_` plus full SHA-256 of a canonical remote identity, `local_` plus full SHA-256 of machine identity and canonical repository root for remote-less repositories, or `unassigned`. Hashes have negligible collision risk, not a mathematical guarantee. Remote-less repositories cannot share identity across machines without a remote.

Canonical remote identities remove credentials, query, fragment, trailing slash and `.git`, collapse SSH scp and HTTPS spellings, lowercase hostname, preserve generic repository path case, and case-fold GitHub paths. Preserve non-default service ports. Prefer origin, otherwise deterministic first remote. Resolve git worktrees through git metadata rather than directory names; resolve subdirectories to root. Use execFile with argument arrays and bounded timeout, never a shell. No persisted remote credentials, local paths or machine identifiers are returned in API labels. Machine fallback uses an existing OS machine identifier when available, with a persisted random local ID only when necessary. Resolution caches are bounded and invalidate when git configuration changes.

For live local capture, derive from execution cwd rather than trusting an arbitrary label. For hosted capture, preserve a validated incoming projectKey or resolve explicit remote metadata; never infer the hosted server checkout as the customer's project. Hosted cwd strings are not executed or read on the server. Invalid project keys return 400 at the API boundary. Project values are not path fragments.

Historical attribution follows the evidence-only revision below. Existing valid identities stay stable. Recorded execution paths may supply additional evidence only through an explicitly enabled, bounded local metadata probe; hosted customer paths never resolve against the server filesystem. A legacy scope identifier still becomes `legacy_` plus SHA-256 of the exact identifier when no unique canonical mapping is proven. Never merge repositories by basename or use the migration process cwd. Missing or conflicting evidence remains visible with reason counts.

The earlier dry-run counts remain baseline observations, not a target quota. No raw row samples, command text, filesystem paths, remote credentials or machine identifiers enter the report. The frozen 13-file snapshot manifest and per-row baseline receipt live privately in `/tmp/project-scope-attribution-snapshot.json` and `/tmp/project-scope-attribution-baseline-rows.json`; compare file ordinal and row hash, not mutable live logs.

The resolver remains pure: a separate evidence collector produces bounded lookup indexes and optional verified local-path results; `projectForRecord` consumes those inputs without filesystem or process access. Dashboard, migration, lessons, generated gates and exports share that same decision function. No eager disk probing occurs merely because a hosted request supplies a path. Existing descriptors and tenant-first root containment remain unchanged.

Candidate fields are an explicit allowlist finalized against the audit. Audited classes are `toolInput.repoPath`, `toolInput.file_path`, `toolInput.tool_input.file_path`, their explicitly named cwd/file-list equivalents, exact session identifiers, and explicitly project-bound hook execution directories. `toolInput.command` and `toolInput.tool_input.command` permit only the conservative literal syntax described below. Arbitrary nested strings, free-form context, stack traces, executable names, generic hook names and installed harness source directories are not paths to probe. A hook script installed inside the ThumbGate package is not evidence that the user's action belongs to ThumbGate. Session IDs and hook names alone are never project identities.

The account index is built in explicit passes: collect original immutable descriptors, remotes and causal references; probe approved path candidates; establish exact scope mappings and session anchors; classify remaining rows. Session-derived rows never become anchors for other session rows or prove a scope alias. Every propagation retains its originating evidence class. `accountAttribution` must preserve minimal schema-allowlisted evidence through collection: typed record IDs/references, registry project and agent ID, scope, provenance/machine markers, timestamps, session IDs and admissible path/command fields. Do not drop these fields before resolution or retain full context/payload content unnecessarily. Cyclic or unresolved causal references remain Unassigned. Source IDs do not cross account roots even when directory names, IDs, paths or sessions are identical.

**Historical certainty and directory reuse.** Per the owner's explicit request, a genuine recorded local execution/target path plus the currently verified Git remote is admissible without an additional event-time corroboration requirement. Label it `path_remote_current`: this establishes the repository currently at the recorded path, not a contemporaneous remote snapshot. If recorded remote/scope/causal evidence contradicts the current path, preserve stronger identity or quarantine a row without resolved identity. Never overwrite a known project to improve counts. Explicit imported or foreign-machine provenance still forbids local probing.

**Machine and account provenance.** Path probing requires explicit collector options describing a trusted local-origin account source and approved repository roots. Those options come from the operator/runtime, never an HTTP body or a historical row. A recorded machine identity that disagrees, imported/synchronized provenance, or an unknown source-machine relationship disables probes for that row. The owner explicitly attests the original local `~/.thumbgate` log corpus and its frozen snapshot manifest as local provenance, including older rows without machine identifiers. This attestation is passed as collector configuration; copying another arbitrary directory or supplying an HTTP path does not acquire it. Explicit imported/remote-machine evidence overrides that corpus-level attestation. Hosted migration and hosted reads have path probing disabled. The local HTTP runtime supplies trusted collector options only after account binding, for loopback requests using the configured local feedback root, with approved roots `~/workspace` and `~/.herdr/worktrees`; HTTP-selected filesystem roots never gain this policy. Hosted tenant/deployment requests remain disabled even when served through loopback. Hosted rows may still resolve from recorded remotes, preserved descriptors, exact same-account causal relationships, exact scope mappings and admissible session anchors. A remote machine's `/Users/...` or `/workspace/...` string never selects a path on the hosted server. The existing account root is the boundary for row indexes, not proof that a client path exists on the server.

**Registry linkage verified from writers.** `registerAgent` records `project` from its argument or `basename(process.cwd())`; that is a meaningful legacy label, not proof that equal basenames denote the same Git repository. MCP bootstrap registers a generated `agent_<timestamp>_<random8>` ID when none is supplied and exports that exact ID through the session/agent environment. The gate observer records the same acting ID, and audit/KPI rows record it as `agentId`. Caller-supplied IDs are permitted only when the full same-directory registry history has one unanimous meaningful identity; conflicting reuse is a permanent conflict sentinel for that pass. Do not require the session heuristic's arbitrary 24-hour interval for an explicit registry-to-agent-event relation: retirement changes authorization state, not the recorded identity of an observed actor. Events with contradictory direct evidence keep their higher-priority attribution. No substring, agent-name-to-repository or most-recent-row match is permitted.

**Conservative command syntax.** Only the two audited command fields are parsed, never executed. A bounded tokenizer may extract literal absolute directories from `cd <directory>` and `git -C <directory>`, and literal absolute file/directory operands from an explicit set of file-inspection commands (`cat`, `head`, `tail`, `wc`, `ls`). Quoted literal tokens are supported; variable or tilde expansion, command substitution, backticks, heredocs, embedded source code and unsupported shell constructs are not evaluated or mined for path-looking substrings. Do not treat a program's executable/script path, option value of unknown meaning, URL, redirect or echoed prose as the originating project. Reject truncated or redacted commands/path tokens. Search-pattern commands (`rg`, `grep`, `sed`, `find`) and unknown option forms such as `ls -I` are excluded; `git -C` is recognized only as an initial global option, never inside commit arguments or after `--`. Multiple eligible paths must agree on one remote; conflicts remain unresolved. Record command extraction as a subkind of `path_remote_current` and report rejected syntax separately. Structured path fields remain independently usable when command text is rejected.

**Bounded metadata probe.** No shell, Git process, hook, subprocess, credential helper, environment expansion, network call, recursive repository scan or config include is executed. Only directory metadata and these known Git metadata files may be read: `.git` pointer, repository `config`, worktree `commondir` and worktree `config.worktree`. A root/metadata path must pass both lexical and real-path containment under explicitly approved roots. Refuse symlink escapes, non-regular metadata files, unsupported config includes and conflicting origin URL declarations. Parse only the remote URL sections needed by the existing origin/first-remote identity rule; unsupported syntax yields an explicit reason rather than a guessed parser result. Metadata filenames are fixed by the collector, not concatenated from row-controlled filenames. No file referenced by a config include is read.

`accountAttribution`, `readProjectRows`, `buildProjectCatalog` and `migrateProjectScope` accept `localPathEvidence: { trustedLocalSource: true, allowedRoots: [...], sourceMachineId?: string }`. No probing is the default. Counts expose `evidence`, `reasons`, `unassignedReasons`, `anchorEvidence`, `canonicalAttributed`, `legacyAttributed`, `localAttributed` and `pathProbe`; the three attributed identity totals sum to `attributed`.

Default ceilings per account collection: 16 candidate paths per row, 4 KiB per path, 32 ancestor directories per candidate, 4,096 distinct candidates, 256 KiB per metadata file and 16 MiB total metadata bytes. Excess is counted as `probe_budget_exceeded`; the count report includes candidates considered/probed/skipped and never presents a capped pass as complete. An in-memory cache is bounded to those candidates and scoped to account, source machine, approved roots and policy version. Index compact identity descriptors and allowlisted candidate summaries, never whole `toolInput` objects or duplicated row payloads. Positive entries track metadata inode/size/mtime fingerprints; a changed fingerprint invalidates the entry. Negative entries live only for that collection. Dry runs write no cache, machine ID or source file. Cache results never cross account or machine namespaces.

Any path token ending in truncation markers (`...` or `…`), containing NUL/control characters, or known to have been truncated by `sanitizeToolInput` is rejected in full; never walk its parent as evidence. A recorded cwd/repository directory must exist to be probed. For a structured file path, one missing leaf is permitted if its recorded parent directory exists and resolves inside an approved repository; missing directory chains or absent repositories remain unresolved. Relative paths require an admissible recorded cwd and cannot escape it through `..`; never resolve against the migration/server cwd. URI, UNC/network and unsupported platform paths remain unprobed. A Git repository without a canonical remote is not assigned a new machine-local identity during a historical dry run unless its source-machine/root binding was already recorded and matches the existing identity contract. ## Alternatives Rejected

- Package names and directory basenames cannot identify repositories uniquely.
- Moving source histories into project subdirectories would break legacy readers and require risky dual writes.
- Temporary filtered copies per HTTP request add IO, sensitive copies and snapshot races.
- Filtering finished responses leaves cross-project aggregate counts and ranking leaks.
- AsyncLocalStorage or a global current-project variable hides dependencies; explicit query options are reviewable.
- Rewriting online JSONL while writers append can lose data. Keep migration offline and support read-time attribution until maintenance.
